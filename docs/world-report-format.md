# ワールドレポートの記録形式（試案 v0.3）

「その場所の情報」と「その日に自分が感じたこと」を、混ぜずに一緒に残すための小さな約束です。VRChatの公式規格ではなく、VRMのような既存の標準との互換性もありません。まず個人の記録から始め、使いながら項目を見直します。

## なぜ用意したか

自由な文章だけでもレポートは書けます。ただ、記録が増えると「どこだったか」「いつ、どの環境で行ったか」を揃えて探すのが難しくなります。そこで、ワールドURLや訪問条件を共通の欄に分け、感想は箇条書きで自由に残します。

同じワールドでも、更新や訪問時の条件で体験は変わります。ワールドIDは場所の識別、レポートIDは一回の記録の識別に使います。再訪を上書きする必要はありません。

将来はSQLで条件を絞り、文章検索やAIによる自然文の検索を組み合わせたいと考えています。**現在のツールにはAI検索・ベクトル検索・LoRA学習は実装していません。** 現在できるのはSQLiteへの蓄積と文字列検索、素材の受け渡し、記事の編集・投稿です。

## 使い方

1. [テンプレート](../templates/world-report-v0.3.md) をコピーする。アプリなしでも使えます。
2. URL・名前・作者などの確認済みの基本情報を書く。
3. 訪問日と実際に使った環境を書く。「PCで訪問した」と「PCのみに対応している」は別の情報です。
4. SARを軸に、本文用フォームへ体験の詳しい流れや補足を箇条書きにする。全欄を埋める必要はありません。
5. 写真と短い説明を添える。記事化しても元のメモは残します。
6. 記事を自分で読み直してから公開する。

たとえば、仮の記入例なら「窓際に座って雨音を聞いた」「一人で落ち着きたいときによさそう」で十分です。作者が「軽量」と説明していても、自分の端末で確認していなければ快適だったとは書きません。

## 項目とアプリ内データの対応

| 内容 | 保存項目 | 扱い |
| --- | --- | --- |
| ワールドID・URL・名前・作者 | world.id / url / name / author | 場所の識別と基本情報 |
| 作者の説明・対応環境・定員 | world.description / platforms / capacity | 取得情報。感想とは分ける |
| 取得元・取得日時 | world.source / fetchedAt | 自動取得なら取得元と時刻を保存。手入力では確認日をメモで補える |
| 訪問日・訪問環境 | visitedAt / environment | 今回の体験の条件 |
| 記事全体で伝えたいこと（任意） | notes.summary | 旧「ひとことでいうと」の入力も維持 |
| 景色・空間の補足 | notes.scenery | 見たこと・感じたこと |
| 音・音楽・演出の補足 | notes.sound | 実際に聞いたこと |
| 体験した順序・遊び方 | notes.activities | 体験したこと。作者説明だけならその旨を書く |
| 印象に残った場面・自分の感想 | notes.highlights | 個人の感想 |
| 訪問前に伝えておきたいこと | notes.concerns | 個人の感想。なければ空欄 |
| 楽しみ方・向いていそうな人（任意） | notes.recommended | 自分が勧めたい用途や人 |
| 体験の流れ | experience.scene / action / result | 同じ訪問体験の場所・行動・その結果 |
| 旧4項目 | brief.what / who / how / why | 過去の素材として保持し参照 |
| 訪問時の補足 | articleMaterial.visitContext | 同行人数など。ワールドの仕様とは区別 |
| 記事化の希望 | articleMaterial.focus / omit | 重点・残したい言い回し / 公開文に含めない内容 |
| 写真・説明 | photos / caption | メモと対応する写真 |
| 記事タイトル・本文 | title / body | 編集・添削後の文章 |
| レポートID・版 | id / revision | 一回の記録の識別と変更管理 |

自由記述のメモを一律の評価点や固定タグに変換する規格ではありません。「未確認」「非対応」「該当しない」を区別します。未確認の値は空文字・空配列・nullとして保存する項目があり、項目ごとに型が異なります。現段階では、アプリ間交換のための厳密なJSON Schemaは提供していません。

## バージョンと保存

人が記入するテンプレートの版は **v0.3**、アプリの内部保存形式は **schemaVersion: 1**。これらは別のバージョンです。今回のアプリ配布版は **v0.3.3** です。

SQLiteが原本です。Codexにはinput.json・request.md・写真を渡し、article.mdを取り込みます。review.jsonとedited.mdは保存内容の控えです。内部JSONを直接編集してもSQLには反映しません。既存の個人データやAPIキーはGitHubへ公開しません。

ツールの紹介記事など、訪問を伴わない記事はkind: articleとして取り込み、ワールド情報を捏造せずに保存・投稿します。通常の記録はkind: world-reviewです。kindがない旧データはworld-reviewとして読み込みます。

## 冒頭文とツイート（v0.3、SAR）

目的はJoin前に体験を具体的に予想できる文章にすることです。experience.scene（場所・環境）→ action（訪問者がすること）→ result（その行動で見える・聞こえる・体験できること）を同じ体験の流れとして記録します。

原則3行の本文にし、完成文にはSARのラベルを出しません。景観なら眺める・散策する・撮影することも行動です。写真で分かる景色は簡潔にし、音・演出・仕組みは確認できた記録だけを補います。未確認の内容は創作せず、材料が足りなければ1〜2行に留めます。

sharing.openingは記事の冒頭文、sharing.tweetは3行を目安にした本文、sharing.includeOpeningは記事先頭への使用指定です。Codexはarticle.mdとsharing.json（{"opening":"冒頭文", "tweet":"場所の文\n行動の文\n結果の文"}）を作成します。openingは2〜3文で自然につなぎ、article.mdと重複させません。アプリの草稿ボタンは入力文を整形するだけで、自然な文章への推敲はCodexと人の添削で行います。

完成文とコピーできる雛形は、本文 → 確認できた対応環境 → 末尾の順です。末尾は以下で固定します。

```text
World：【ワールド名】
【公開用ワールドURL】
#VRchat #VRChatワールド紹介
```

APIのunityPackagesから取得したworld.platformsに応じて、PC / Quest単機 / スマホ(Android) / スマホ(iOS)のうち確認できた環境だけを追加します。Android / Quest（android）はQuest単機とAndroidスマホ、iOSはiOSスマホ、PC（standalonewindows）はPCです。未取得・未知の値は表示せず、「PCのみ」「非対応」とは断定しません。iOS向けパッケージがない場合のAndroid版フォールバックからiOS対応を推定しません。

ワールド名・URL・2タグ・対応環境も文字数に含めます。本文に余分なURLやタグがある場合、または通常の上限を超える場合はコピーを止めて修正を促します。ツイート本文そのものは添削できます。Xへの自動送信は行いません。

## 旧データとの互換性

SQLiteが原本です。旧データに空のexperienceを補って読み込みます。schemaVersionは1のまま、既存のメモ・写真・冒頭文・本文・ツイート・投稿先を保持します。旧briefは参照用に残し、特にWhoやWhyを結果へ機械的に変換しません。旧sharing.hashtagも保持しますが、完成文では固定の2タグを使います。

Codex依頼後にSARや素材・添削文が変わると古い出力の取り込みを止めます。移行前に作った依頼も安全のため作り直してください。「Codexに渡す」を実行するとarticle.mdとsharing.jsonを両方退避し、新しい依頼を作成します。input.jsonのcommunicationにはフレームワークの版（SAR-v1）と対応環境・末尾を含め、Codexが完成文全体の長さを考慮できるようにします。

review.json・edited.md・edited-sharing.json・tweet.txtは控えです。tweet.txtは草稿なので、使う前にツールの文字数・タグの検証を確認してください。

参考：[VRChatの対応プラットフォーム](https://creators.vrchat.com/platforms/)


## はてな記事本文の入力（アプリv0.3.1）

SARの下は「訪問の記録」「本文に残す体験」「記事化の希望」の3つに整理します。SARと重なる要約やおすすめを必須にせず、体験の順序・感覚の補足・本人の感想・注意点を本文用の材料として残します。既存のnotesのキーと値は維持し、旧summary / recommendedは編集できる補足欄へ移します。既存の本文を自動変換しません。

articleMaterialは追加の任意項目です。旧データでは各文字列を空欄で読み込みます。visitContextは訪問条件、focusは編集の重点、omitは記事・冒頭・ツイートに含めない指定です。これらを変更した後は、以前に生成された出力をそのまま取り込めません。記事化を依頼し直してください。

生成時は入力欄の並びをそのまま見出しへ変えず、SARと体験メモ・写真を整理し、内容のある見出しだけを作ります。omitの内容そのものを公開本文へ列挙しません。入力欄はコマンド実行や公開の権限を与えません。


## ツイート専用の受け渡し（アプリv0.3.2）

作成範囲は入力素材と別に選びます。generationMode: tweet-onlyの依頼はoutputs: {"tweet":"tweet.json"} を持ち、tweet.jsonの {"tweet":"本文"} だけを取り込みます。openingは不要で、余分なキーは拒否します。既存の記事本文・タイトル・冒頭文・article.md・sharing.jsonを維持します。専用依頼の作成時は古いtweet.jsonだけを退避します。

一括作成はgenerationMode: articleで、従来のarticle.mdと任意のsharing.jsonを使います。移行前のgenerationModeがない依頼も一括作成として読み込みます。取り込みモードが異なる場合は拒否し、間違って記事へ反映しません。専用依頼でも素材・本文・添削済みツイートが変わった場合は依頼を作り直します。保存スキーマは変更しません。


アプリv0.3.3の生成指示では、world.descriptionも特徴の材料として明示し、行動と結果の言い換えや汎用的な結びを推敲します。50字への圧縮を目標にせず、末尾を含めた280カウントの範囲で具体的な体験を残します。作者情報を本人の実体験にすり替えず、未確認の演出や健康効果を創作しません。
