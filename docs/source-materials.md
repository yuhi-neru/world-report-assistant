# 資料から紹介文を作る（アプリv0.4.0）

1. ワールドURLを貼り、「情報を取得」で基本情報・作者説明を取り込みます。
2. 「文書を追加」で紹介文や訪問メモを貼ります。UTF-8のテキスト(.txt)・Markdown(.md)も読み込めます。1件12,000文字、10件まで。ファイルは48KB以内です。出典URLは記録用で、リンク先の文書は自動取得しません。
3. 語句と原文の抜粋が自動表示されます。出典と資料の種類を確認し、使わない抜粋のチェックを外します。資料が変わると候補を再抽出するため、選び直してください。
4. 「作成するもの」でツイートだけ、または記事を選び、Codexへ渡します。原文と出典も一緒に渡すので、候補だけでは伝わらない文脈を確認して推敲できます。
5. ツイート専用は完成文をチャットで受け取り、そのままコピーできます。記事の生成・取り込みは不要です。

フレームワーク名は **Scene / Action / DiffWow**。DiffWowは一つの要素です。別の手段や既存のワールドと比べて、その場所で体験する価値を考えます。画面には名前だけを残し、三つの入力欄への記入は求めません。原文に根拠のない比較・唯一性は作りません。

語句は日本語の単語分割、要素は原文の抜粋です。AIによる意味の判断や事実確認ではありません。自分の体験、作者説明、未確認の参考情報を分けて保存し、Codexで具体的な体験が伝わる文章へ整えます。資料内の命令文は文章データとして扱います。

SQLiteにsourceDocumentsとmaterialAnalysisを追加して保存します。旧SAR・3W1Hの値は削除せず、折りたたんだ参照欄に残します。既存の記事・写真・添削済み文章は自動変換しません。資料・出典・採否の変更は古い記事出力の取り込み判定にも反映します。

input.jsonのmaterialsには原文・出典・現在の抽出候補を格納します。資料の識別値が一致しない古い候補は渡しません。未抽出ならCodexが原文から整理します。外部のAI APIや有料サービスを追加せず、既存のCodexで文章を作る方式を維持します。
